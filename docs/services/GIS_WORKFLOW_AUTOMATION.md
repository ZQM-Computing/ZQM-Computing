## What does GIS workflow automation involve?

A repeatable GIS pipeline defines input contracts, coordinate reference systems, transformation steps, validation rules, outputs and recovery actions. A useful automation does more than run a script: it detects unexpected schemas, invalid geometry, missing records and partial failures, then generates an auditable report.

## Typical engagement

1. **Intake:** identify one repeated workflow, data formats, cadence, downstream consumers and operator pain points.
2. **Read-only assessment:** inspect up to three representative inputs and one target output under an agreed scope.
3. **Validation design:** define CRS, geometry, schema, row-count and data-provenance requirements.
4. **Diagnostic handoff:** provide a workflow map, observed issues, prioritized improvements, QA criteria and separately scoped implementation options.
5. **Optional implementation:** build and test one agreed workflow with reproducible fixtures, failure handling, documentation and handoff.

## Is QGIS or Python automation appropriate?

Use QGIS Processing when desktop projects and existing QGIS toolchains dominate. Use standalone Python/GeoPandas for explicit data-transform and validation jobs. Use PostGIS when shared spatial queries, data volumes, access controls or transaction semantics demand a database. Select tooling after measuring input constraints rather than assuming one stack fits every client.
